# @std.io

Byte streams and the standard streams.
The module relies on file-next-to-folder resolution: `@std.io` is the file `io.ens`, and the pieces live under `io/`.

## Layout

```
libs/std/src/io.ens          out(), err(), in(), flush()
libs/std/src/io/print.ens    print, eprint (the prelude module)
libs/std/src/io/streams.ens  IoError, ErrorKind, Reader, Writer, copy
libs/std/src/io/buffered.ens BufferedReader, BufferedWriter
libs/std/src/io/text.ens     TextWriter
libs/std/src/io/memory.ens   BytesReader, BytesWriter
```

`print` and `eprint` live in their own module, `@std.io.print`, because the prelude lends every exported function of a module it lists and only these two belong there (ratified 2026-09-03).
The implicit import list is `@std.core` and `@std.io.print`; `out`, `err`, `in`, and `flush` stay reachable as `io.out()` and the like.

## Standard streams

```ens
// @std.io
// The streams every process is born with.

export out() -> Writer;             // standard output, buffered
export err() -> Writer;             // standard error, unbuffered
export in() -> BufferedReader;      // standard input, one shared reader

// Everything accepted by `out` but not yet given to the operating system, handed over.
export flush() throws IoError;

```

```ens
// @std.io.print
// One value, written to standard output or standard error with a newline after it. These two live
// in the prelude, so no program imports anything to say something.
export print(string message);
export eprint(string message);
```

`in()` answers the same `BufferedReader` every call.
Sharing one read-ahead buffer is enforced rather than advised, because bytes read ahead from stdin cannot be pushed back; two independent readers would silently steal from each other.
`io.in().readLine()` is the way a program reads a line.

## Streams

```ens
// @std.io.streams
// The two contracts a stream of bytes moves through. Files, pipes, memory buffers, and the
// standard streams all speak these, so code written against them runs on any of them.

export class IoError extends Error {
    export const ErrorKind kind;
    export constructor(this.message, this.kind, Error? cause = null);
}

export enum ErrorKind {
    Closed,
    Interrupted,
    Other,
}

// A source of bytes. `read` fills as much of `buffer` as it has ready and answers how many bytes
// it wrote, or 0 once the stream has ended. A short answer is not the end: ask again.
export interface Reader {
    read(byte[] buffer) -> long throws IoError;
}

// A destination for bytes. `write` takes all of `data`; `flush` hands everything accepted but not
// yet passed on to wherever it goes.
export interface Writer {
    write(byte[] data) throws IoError;
    flush() throws IoError;
}

// Moves everything `source` has left into `target`, and answers how many bytes moved.
export copy(Reader source, Writer target) -> long throws IoError;
```

## Buffering

```ens
// @std.io.buffered
// Wrappers that turn many small reads and writes into few large ones.

// Reads ahead into a buffer, and adds the line-shaped reads raw readers cannot offer.
export final class BufferedReader implements Reader {
    export constructor(Reader source);
    export constructor(Reader source, long capacity);

    export override read(byte[] buffer) -> long throws IoError;

    // The next line without its ending, or null once the stream has ended. Output that does not
    // end in a newline is a last line of its own.
    export readLine() -> string? throws IoError;

    // Everything left, as bytes or as text.
    export readAll() -> byte[] throws IoError;
    export readAllText() -> string throws IoError;
}

// Collects writes into a buffer and passes them on when it fills, when `flush` is called, or when
// the wrapper is dropped. The drop flush cannot report failure, so a program that must know calls
// `flush` itself.
export final class BufferedWriter implements Writer {
    export constructor(Writer target);
    export constructor(Writer target, long capacity);

    export override write(byte[] data) throws IoError;
    export override flush() throws IoError;

    // Flushes what the buffer still holds, keeping any failure to itself.
    destructor();
}
```

## Text writing

```ens
// @std.io.text
// Writing text onto a byte stream. The text goes out as its UTF-8 bytes.
export final class TextWriter {
    export constructor(Writer target);

    export write(string text) throws IoError;
    export writeLine(string text) throws IoError;
    export writeLine() throws IoError;
    export flush() throws IoError;

    // Flushes what is still held, keeping any failure to itself.
    destructor();
}
```

## Memory streams

```ens
// @std.io.memory
// Streams over bytes already in memory, for assembling output and for testing anything that
// speaks Reader or Writer.

export final class BytesReader implements Reader {
    export constructor(byte[] source);
    export override read(byte[] buffer) -> long;
}

export final class BytesWriter implements Writer {
    export constructor();
    export override write(byte[] data);
    export override flush();

    export toBytes() -> byte[];
    export length() -> long;
    export clear();
}
```

## Decisions embodied here

Stream operations throw `IoError` everywhere, including `File.read`; `FileSystemError` is for path-shaped operations.
This is the one deliberate bend in the one-error-per-module rule, and it keeps `copy` writable with one throws clause.
Buffering is by wrapper, not built into the interface: the buffer-in-interface design would force `Writer` to be an abstract class with fields, which single inheritance cannot afford, and it would make every writer flush-critical in a language with no `defer` and non-throwing destructors.
`out()` is buffered, `err()` is unbuffered, so errors survive a crash.
`TextWriter` does not implement `Writer`: it is not a byte sink, and offering both writes on one object is the mixed-hierarchy confusion Java's streams are criticized for.
`Reader` and `Writer` are byte-only, not generic: a stream of values already has a name, `Iterator<T>`, and conflating the two is a known mistake elsewhere.
`BytesWriter` has no `toString`: `toString` is total, and arbitrary written bytes may not be valid UTF-8, so text extraction is spelled `string.fromBytes(w.toBytes())` or `fromBytesLossy`, through the one existing gate.
No `Seek` in v1; files can grow positional reads later without touching the interfaces.
`readLine` lives on `BufferedReader` only, so line logic exists once; `LineBuffer` and `ChildProcess.readLine` both dissolve into it.
The runtime keeps its existing forced flush before diagnostics, before a child starts, and before a panic is reported.
